## 確認・実装内容
- 未編集のアンケートに対し編集ボタン押下→編集画面遷移のタイミングでロックを取得（DB格納）する
- 編集中は定期的にロックを更新し、ロック状態を保持する
- 編集中のアンケートに対し、ダッシュボードの編集ボタン押下で「誰かが編集中です」モーダルが表示される
- 編集中のアンケートに対し、ダッシュボードの削除ボタン押下で「誰かが編集中です」モーダルが表示される
- 更新ボタン押下で、公開予定データが上書きされ、`sessionStorage`が破棄され、ロックが解放される
- 確認画面でもロックが維持される（未実装であれば実装する）

## 併せて確認するアンケート編集全般の項目
- [ ] ダッシュボードから編集画面へ遷移できるのは「下書き」「公開予定」のみ
- [ ] 編集ボタン押下時、ステータス・データ（タイトル、問題、選択肢、必須設定モーダルの内容含む）が編集画面に正しく引き継がれる。この時点ではDB更新されない
- [ ] 確認画面遷移時・修正ボタン押下時は`sessionStorage`のデータを使用し、DBには格納しない
- [ ] 確認画面からの離脱時：下書き編集はDB更新、公開予定編集は変更内容破棄。いずれの場合も`sessionStorage`を破棄する
- [ ] 管理者削除・更新時、`delete_flag`で管理されている
- [ ] 確認画面から更新を押すと、いずれのケースもステータス`created`でDB更新され、`sessionStorage`が破棄される

## 完了確認チェックリスト（ロック関連）
- [ ] 編集画面遷移時にロックが取得される
- [ ] 編集中、定期的にロックが更新され保持される
- [ ] 他ユーザーの編集ボタン押下時に「誰かが編集中です」モーダルが表示される
- [ ] 他ユーザーの削除ボタン押下時に「誰かが編集中です」モーダルが表示される
- [ ] 更新ボタン押下でデータ上書き・`sessionStorage`破棄・ロック解放がすべて行われる
- [ ] 確認画面でもロックが維持される
